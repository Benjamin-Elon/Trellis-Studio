# Allocation lifecycle and overlapping planting context <!-- CHANGE -->

Allocation dates, year, season and timing comparisons are calculated from the demand window and remain read-only. **Lock lifecycle** starts checked. Unlocking enables the existing method, transplant lead-day and harvest-duration controls. Each edit solves demand timing again and revalidates capacity and coverage for the same crop, variety, growth stage, bed and demand window. Relocking retains the edited settings. Task customization remains available. Ordinary scheduling keeps its existing editing behavior. <!-- CHANGE -->

Comparisons include every valid planting whose occupancy overlaps in the same bed. Bed start means transplant/bed entry for transplants, sow date for direct sowing, and planting/lifespan start for perennials. Actual offset is proposed bed start minus the other bed start. Recommendations are normalized to that direction; the difference is described as earlier or later. Unknown recommendations remain unknown. Repeated crop/variety names receive planting numbers and exact dates. These comparisons are informational and do not change dates or conflict rules. <!-- CHANGE -->

Other starts use separate label lanes aligned with the current timeline axis. Starts outside its range are omitted from the timeline while retaining their comparison rows. The axis is never extended to include them. Malformed occupancy intervals are skipped without discarding valid comparisons. <!-- CHANGE -->

The footer exposes two independent choices on both tabs. **Save companion-set spacing as default** starts checked only when the active overlapping set has no applicable exact or plant-level saved set default. It saves the whole active set's final spacing and bed offsets through the existing set-default model, never timing recommendations. **Save lifecycle settings as defaults** starts unchecked and identifies the selected variety or plant. Opting in saves method/category, transplant lead days and harvest duration; variety JSON merges preserve unrelated overrides and empty method/category values inherit plant defaults. Explicit schedule methods remain authoritative. <!-- CHANGE -->

Preview and revalidation retain lifecycle preferences, comparisons and deferred default writes. Preview, cancellation and failed creation write no reusable defaults. Defaults commit after planting and tasks are successfully created. Save failures then use the existing allocation notification. First-time lifecycle writes also require opt-in; existing task-default behavior is preserved. A failed fit clears calculated results and disables both Preview actions. Edit versions, closed-dialog checks and allocation identity checks prevent obsolete async results from publishing. <!-- CHANGE -->

Validation covers locking, demand refits, indoor/direct-sow offsets, both recommendation directions, duplicate crops, missing/malformed data, off-axis starts, exact/broad default selection, plant/variety persistence and inheritance, preview/cancellation, failed creation and post-creation save failures.
