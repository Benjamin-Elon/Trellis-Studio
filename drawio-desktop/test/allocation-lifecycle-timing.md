# Allocation lifecycle and overlapping planting context <!-- CHANGE -->

Allocation dates, year, season and timing comparisons are calculated from the demand window and remain read-only. **Lock lifecycle** starts checked, except required-default setup opens an absent method default for editing. Unlocking enables the existing method, transplant lead-day and harvest-duration controls. Each edit solves demand timing again and revalidates capacity and coverage for the same crop, variety, growth stage, bed and demand window. Relocking retains the edited settings. Task customization remains available. Ordinary scheduling keeps its existing editing behavior. <!-- CHANGE -->

Comparisons include every valid planting whose occupancy overlaps in the same bed. Bed start means transplant/bed entry for transplants, sow date for direct sowing, and planting/lifespan start for perennials. Actual offset is proposed bed start minus the other bed start. Recommendations are normalized to that direction; the difference is described as earlier or later. Unknown recommendations remain unknown. Repeated crop/variety names receive planting numbers and exact dates. These comparisons are informational and do not change dates or conflict rules. <!-- CHANGE -->

Other starts use separate label lanes aligned with the current timeline axis. Starts outside its range are omitted from the timeline while retaining their comparison rows. The axis is never extended to include them. Malformed occupancy intervals are skipped without discarding valid comparisons. <!-- CHANGE -->

The footer exposes independent default choices on both tabs. **Save companion-set spacing as default** starts unchecked and retains explicit opt-in through schedule review. It saves the whole active set's final spacing and bed offsets through the existing set-default model, never timing recommendations. **Save lifecycle settings as defaults** starts unchecked for optional updates, but is checked and disabled when a planting-method default is required. Opting in saves method/category, transplant lead days and harvest duration; variety JSON merges preserve unrelated overrides and empty method/category values inherit plant defaults. Explicit schedule methods remain authoritative. <!-- CHANGE -->

Preview and revalidation retain lifecycle preferences, comparisons and optional deferred default writes. Ordinary **Preview Planting**, cancellation before Save, and failed creation write no optional reusable defaults. **Save defaults & preview** explicitly saves missing required records before creation; those saved defaults remain if allocation is later cancelled. Optional lifecycle updates and spacing defaults commit after planting and tasks are successfully created. A failed fit clears calculated results and disables both Preview actions. Edit versions, closed-dialog checks and allocation identity checks prevent obsolete async results from publishing. <!-- CHANGE -->

Validation covers locking, demand refits, indoor/direct-sow offsets, both recommendation directions, duplicate crops, missing/malformed data, off-axis starts, exact/broad default selection, plant/variety persistence and inheritance, preview/cancellation, failed creation and post-creation save failures. Browser QA uses the actual scheduler with in-memory data at normal and narrow dialog widths. <!-- CHANGE -->

## Inline allocation occupancy and spacing <!-- CHANGE -->

The above-bed preview starts in **Occupancy**, showing the existing coverage and occupancy timelines. **Spacing** hosts the planting overlay's shared editor with X/Y spacing and X/Y internal-grid offsets in centimeters. It remains available for a selected crop and bed when no plants fit. A crop with valid lifecycle timing but insufficient default-spacing capacity appears under **Adjust spacing to fit** in the allocation crop selector. <!-- CHANGE -->

Ordinary allocations resize to demand, rounding to complete surviving rows. Offsets retain their entered X/Y axes through bed rotation and affect in-bounds capacity, placement and overlap. Capacity shortages produce partial coverage; extreme offsets or invalid input clear the preview and disable review/Create while leaving the editor usable. Count, demand served, coverage consequences and warnings publish together from the latest calculation. Input nodes, focus and unfinished numeric values survive live recalculation and view changes. <!-- CHANGE -->

**Add as companion** completes any required lifecycle setup and opens inline Spacing. Choose an overlapping companion footprint when several are available. Both crops use that existing footprint; crop selection and **Aligned/Staggered** controls remain available. Source planting edits stay in memory until Create commits them with the new planting and tasks in one undoable transaction. Cancellation and failed creation leave the saved planting unchanged. Selecting another target discards both crops' previous pair edits and initializes the new pair through the shared layout service. <!-- CHANGE -->

Ordinary crop overrides remain separate from crop defaults and survive week, bed, rotation and schedule-review changes for that crop. A crop change or allocation close resets them. Switching away from a companion bed restores ordinary overrides. Spacing **Save as default** starts unchecked; successful Create is required before spacing defaults are written. Existing single-crop persistence stores X/Y spacing, so ordinary offsets apply to the allocation only; companion-set defaults store both spacing and offsets. A spacing-default save failure reports an error while retaining the successfully created planting. <!-- CHANGE -->

Regression coverage includes initial no-fit recovery, offset-aware demand fitting and partial capacity, rotated beds, committed/preview geometry agreement, raw input and focus retention, rapid-edit ordering, navigation and schedule-review retention, companion target changes, atomic rollback and undo, and opt-in/default-save failures. `planting-preview-electron.test.cjs` checks the actual shared editor and allocation host at 900- and 320-pixel canvas widths, including zoom/pan focus retention. <!-- CHANGE -->

## Create planting and required defaults <!-- CHANGE -->

The allocation control panel exposes **Create planting**. It is disabled while saved defaults are being checked, when the selected crop lacks a planting-method default, a task-recipe default for the chosen method, or saved grown-for stages, and when the preview is invalid or recalculating. Missing records appear as clickable **Planting method**, **Task recipe**, and **Grown-for stage** items. Lookup failures show a separate retry action rather than claiming defaults are absent. The saved records are checked again immediately before creation. Spacing defaults are optional and do not participate in this gate. <!-- CHANGE -->

Click a missing item to open the scheduler at its field or Tasks section. Required fields have an amber outline and **Required default not saved** text; the Tasks tab also identifies a missing recipe. The corresponding save option is checked and disabled, while crop/variety/grown-for identity and demand-derived dates remain fixed. **Save defaults & preview** saves only missing records and returns to allocation without creating planting cells or tasks. Partial failures remain visible on either tab, refresh the remaining missing items, and allow retry without overwriting already-saved defaults. Stage saves from the active setup invalidate caches without cancelling their own dialog. <!-- CHANGE -->

An enabled **Create planting** commits a clean preview and its tasks directly in the existing undoable transaction. Unknown/compatibility warnings, partial fits, absent generated tasks, and companion edits that change a saved crop's count require confirmation. Existing review-suppression preferences cannot bypass that confirmation. Known companion layouts with unchanged source capacity create directly. Cancellation before Save leaves defaults unchanged; cancellation after a successful explicit default save retains those records. <!-- CHANGE -->
