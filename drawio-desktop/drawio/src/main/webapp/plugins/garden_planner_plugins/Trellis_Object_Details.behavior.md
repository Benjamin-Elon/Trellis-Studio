# Object details

Shapes and groups can store independent rich-text details in the optional XML attribute `trellis_details_html`. Details do not replace labels, task instructions, or other metadata. Generated planting visuals resolve to their stable planting group.

Right-click an object and choose **Add details…** or **Edit details…**. The clicked object is added to the selection without clearing other selections. Existing details open automatically for selected objects, without taking focus. Their badges remain visible when objects are deselected. Clicking a badge selects and opens an unselected object, or toggles a selected object's field.

The shared header and placement controls sit above a joined **Additional info / Comments (count)** selector, using the same compact mode styling as the planting-group overlay. Description text opens Additional info; objects with only comments or a private comment draft open Comments. Empty objects start on Additional info. Switching tabs preserves both editor DOM nodes, private text, and the selected tab for the panel's lifetime. Comment-only objects retain badges and their details menu, including read-only access. <!-- CHANGE -->

Comments are individual rich-text entries under **Unresolved** (initially expanded) and **Resolved** (initially collapsed). Both sections show counts and sort by original posting time, newest first, with comment ID breaking timestamp ties. Entries show author and posting time, an edited indicator when appropriate, and resolution author/time plus the earliest deletion date. Section expansion is retained while the panel remains open. <!-- CHANGE -->

Creating and editing comments uses the existing text toolbar and sanitizer, with explicit **Post** or **Save changes**. Save, export, blur, tab switching, and navigation never post a comment. Drafts are private device-local data, isolated by diagram, page, object, user, and edited comment. They survive deselection and reload and support Discard, Copy, and confirmed Reload comment. Storage failures retain drafts in memory, report the limitation, and warn before closing with work that could not be stored durably. Input composition cannot submit partial characters. <!-- CHANGE -->

Comment mutations require enabled Trellis users, an authenticated user, object-edit access, an enabled graph, and an unlocked object. Authors can edit their own comments. Authors, the effective owner from the nearest ownership scope, and admins can resolve/reopen comments, or manually delete them after **30 continuous days resolved** and confirmation. Owners/admins cannot rewrite another author's words. Reopening clears resolution metadata; editing resolved text reopens the comment, and the next resolution restarts retention. Delete eligibility is checked at execution and refreshed at its time boundary. Comments remain readable without mutation permission or when Users is disabled. Existing host undo/redo behavior is preserved. <!-- CHANGE -->

Posted discussion uses optional `trellis_comments_json`, a version-1 envelope containing a comments array. Each record has a stable `id`, `authorUserId`, author-name snapshot `authorName`, sanitized `html`, UTC epoch-millisecond `createdAt` and `updatedAt`, and nullable `resolvedAt`, `resolvedByUserId`, and `resolvedByName`. Unsupported versions and malformed records produce a visible error and block writes without dropping data. New action timestamps allow one minute of model-listener scheduling delay; deletion always uses the complete 30-day interval from the stored resolution time and the device clock. <!-- CHANGE -->

The same lifecycle policy is enforced by both the comment UI and the Users model-change guard, including native attribute and whole-value replacements. Changes re-read current discussion; target baselines reject stale edits and moderation, while unrelated comments are preserved. Retried posts retain their ID to avoid duplicates. Shared diagrams use existing object holds and wait for collaborative save acceptance before clearing private drafts; rejected text remains available for copying, reloading, or retrying. Drafts never enter diagram XML, rendered exports, or synchronization. <!-- CHANGE -->

Each field starts below its object at 320 × 180 screen pixels. Arrow controls choose a side; both dimensions can be resized, with a minimum of 180 × 100. Fields wrap and scroll, track movement and view transforms, and retain the chosen side even when they overlap. Interacting with a field brings it forward. Visibility, side, and dimensions are local preferences keyed by diagram, page, user, and cell ID. Without an existing stable diagram identity or available local storage, preferences remain usable for the session. Preference changes never modify diagram XML.

Field stacking uses CSS z-index and an explicit interaction order, without moving editor DOM nodes during pointer gestures. This preserves native focus, arrow click delivery, and empty-field lifetime; exports use the same interaction order. <!-- NEW -->

Focusing an editable field targets the existing draw.io top text toolbar. The field remains independent of the label editor. Text formatting, fonts, headings, colors, alignment, lists, indentation, and links work on its text selection. Images, tables, horizontal rules, and HTML source editing are excluded. Toolbar menus and dialogs retain the text selection; callbacks cannot target another field. Leaving details restores ordinary toolbar and label-editing behavior.

The shared text toolbar exposes a Bulleted List button immediately after Underline in both details and rich-text label editing. It uses native list toggling for the caret or selected paragraphs, with standard Enter behavior and no persistent pressed highlight. It hides at the same narrow-window threshold as Bold, Italic and Underline. Numbered lists and indentation remain in the alignment dropdown. <!-- NEW -->

The controller wraps `ui.isSelectionAllowed` to permit native caret placement and text selection inside its own editor nodes, including nested rich text. This applies before toolbar activation and also permits copying read-only text. Other events use the original host rule, which is restored on teardown. Editing permissions remain independent of selection. <!-- NEW -->

Additional info typing commits after 500 ms and flushes on blur, deselection, hiding, explicit save, export, and page/file navigation. Ctrl+S invokes normal Save after flushing. Each burst is an undoable model edit. Input composition does not commit incomplete characters. Clearing the description removes its attribute; the badge remains if comments exist, and an empty field remains available while focused. HTML is sanitized on read, paste, and write and normalized deterministically so read/write attribute ordering cannot cause false conflicts. <!-- CHANGE -->

Permissions use the existing cell and task-detail policy. Collaborative input uses existing object holds. Rejected or conflicting edits remain visible with Retry, Copy, and Discard controls. Internal XML snapshots serialize canonical state and never retry rejected drafts. Explicit save/export/navigation waits for pending edits and refuses to silently discard failed drafts. Drafts retained across user changes are hidden from other users and restored for their author. Undo/redo cancels stale autosave timers and refreshes field content.

Exports include Additional info and its badges for currently open fields on the current page, regardless of the selected tab. Discussion and comment-only badges are excluded from SVG, PNG, PDF, and print projections. Posted comments remain in editable diagram data. Description text is measured at the chosen width and exported at an expanded height, anchored to the chosen side. Editing controls are omitted. SVG export uses an isolated graph; desktop PNG/PDF/print use `__trellisDetailsProjection` in the existing export-variable transport. Synthetic rendering cells inherit their owner's layer and never enter the live model or embedded editable XML. Selection-only exports include annotations only for included objects. Other pages do not open their details automatically. <!-- CHANGE -->

`Trellis_Details_Core.js` owns normalization, comment schema/lifecycle policy, placement, description draft scheduling, and export projection. `Trellis_Details_Comments.js` owns comment rendering, explicit commands, and private draft persistence; it is loaded by the existing details plugin. `Trellis_Details_Toolbar.js` owns the active rich-text target and scoped command routing. `Trellis_Object_Details.js` owns graph integration, preferences, tabs, overlays, and lifecycle cleanup. `scripts/update-object-details-runtime.mjs` synchronizes changed host toolbar definitions and minimal startup registrations into both committed runtime bundles; these tab/comment changes require no additional host bundle registration. <!-- CHANGE -->

Desktop startup uses the saved plugin list. `js/diagramly/ElectronApp.js` enables details once for existing profiles using `.trellisObjectDetailsDefault.v1`, preserving other plugins and any later deliberate removal. Restart Trellis to load the migrated list. <!-- NEW -->

The hidden Electron smoke installs the production EditorUi selection gate with the shipped selection hook and toolbar, verifies native mouse caret placement and Chromium input, then renders SVG, PNG, and a multi-page PDF through the desktop export page. Test artifacts are written under `.test-artifacts/object-details`; PDF printing needs the same native Chromium printing service as the application. <!-- CHANGE -->
