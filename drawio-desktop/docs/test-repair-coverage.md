## Weaknesses, failure modes and limits

- Existing equivalent tests must remain present and pass; removing a duplicate fixture is not permission to drop its mapped invariant.
- Local authorized sessions do not qualify gated peer takeover, sharing, handoff or communities.
- Generated provenance records attribution and dependencies; it grants no authority and must not absorb unrelated manual edits.
- Native tests depend on Windows desktop scheduling and must run serially. Controlled callback tests cover stale ownership without relying on timing.
- Signed checkpoint fixtures demonstrate correctness and archive independence, not release performance. Runtime changes invalidate prior source-bound qualification evidence.
- Final acceptance requires unchanged before/after source manifests, no unexpected failures/cancellations/new skips, and a passing production Home smoke. The raw full command can remain nonzero solely for the exact capability scenarios above.

The Home fixture also reproduces a native permission-snapshot defect: metadata written while a cell is detached could resurrect that cell in the reconstructed pre-insertion state. Reconstruction now keeps it absent until an earlier native insertion/removal changes that fact. The connector regression fails before this one-line fix and passes after it; full permission validation still applies.

Field application then revealed a second orchestration mismatch: metadata batching opened a raw model transaction before calling Task Manager’s shared commit runner. Undoable field batches now enter that runner directly; nested task commands join the owner, while non-history IDs/versions/receipts keep their existing suppression. The focused regression checks one command Undo step, durable receipts through Undo/Redo, failure compensation and restored flags.

The startup fence uses a per-discovery token. A superseded callback cannot clear a newer discovery’s native busy flag; when the active discovery is obsolete because the dialog/file changed, it releases its own startup gate. The module-creation fixture observes real initial file completion and asserts that its open request succeeds instead of silently waiting after a refused request.

The first source-stable repair run completed 3,503 Node tests with 41 exact capability failures and one additional obsolete scheduler-navigation assertion; Python, Android and production Home passed. The scheduler test now verifies that Schedule and Tasks tabs retain one draft without prompting, while leaving the editor still supports Stay, Discard and Commit with the dialog retained. Production scheduler edits are preserved. This correction is followed by a second complete, source-stable full run.
