# Responsive desktop startup <!-- NEW -->

Home and the tray initialize from the account and registration metadata. A restored completed license reveals Home controls immediately; the first-time oath completion retains its existing delay. Routine naming and polling leave unchanged unopened gardens deferred. A signed head and the device's signed accepted-position marker can detect incoming work; they never grant document permissions. Changed membership, an explicit refresh, or opening a managed garden requires content verification. <!-- CHANGE -->

Garden Projects displays **Checking garden…** while its selected project is prepared. Native Browse, recent files, and tray opening use the same preparation before reading a managed `.drawio` file. Preparation verifies and materializes only that project. Failure keeps the library available with **Retry opening**. Logged-out standalone and old local-only files retain their existing opening behavior. <!-- NEW -->

Cold checkpoint and accepted-tail verification use the production current-state validators in a data-only worker. One reconstruction runs at a time, with user requests ahead of queued background requests. Workers receive public signatures and project-local reference evidence, never private signing keys. Reconstruction retains its 30-second deadline and 512 MiB heap ceiling. Errors, timeouts, and cancellation have no synchronous replay fallback. <!-- NEW -->

The main process owns receipts, heads, private positions, projection writes, and checkpoint publication through existing project queues. Cancellation invalidates queued and running generations. Verification rechecks the signed head and catches up before returning a ready result. Reference resolution and immutable decoded-XML reuse are scoped to a verification context. Parsed policy is reused only for identical XML, with the current actor and evaluation time. <!-- NEW -->

Checkpoints retain their signed format and 30-decision hard limit. A tail containing at least 4 MiB of serialized accepted envelopes also schedules a coalesced background checkpoint. Only the coordinator publishes one. A soft-budget failure is logged and retried by later reads; it does not change an accepted save into a failure. The required checkpoint still blocks acceptance beyond the hard limit. Archives, registrations, recovery copies, and drafts are retained. <!-- NEW -->

Home defers the existing sidebar palette builders. Editor use or shape search starts scheduled batches that yield between libraries. Saved choices, custom libraries, expansion preferences, and search use the original host mechanics. Failed palette construction offers a retry. The source and shipped runtime bundles share this transformation; `node scripts/update-startup-runtime.mjs` checks it without rebuilding unrelated bundle changes. <!-- NEW -->

Tray presentation receives explicit registration eligibility. It hides retired, fenced, revoked, removed, unsupported, and local-only gardens. Current paused, pending, initializing, and unavailable projects stay visible alongside account rows and the existing controls. This filtering deletes no registrations. <!-- NEW -->

Startup logs report account/registry, tray, and transport timings. Verification logs report durations, checkpoint sequence, accepted-tail bytes, and retryable checkpoint errors without document contents or credentials. <!-- NEW -->

Run `node scripts/check-responsive-startup.mjs` from the desktop project for five sequential native launches with normal graphics and visible windows. The runner creates a disposable remembered account, an approximately 2 MiB garden, eight accepted changes below the old count threshold, and 18 representative registrations. It checks Home controls, the loaded background, and tray against five seconds, then requests cold verification while measuring 100 ms main and renderer heartbeats. Gaps of at least one second fail. Reports and screenshots remain under `.test-artifacts/responsive-startup`; temporary profiles are identified in `results.json`. A previously created disposable fixture path may be passed as the sole argument to repeat measurements. <!-- NEW -->

This workflow never restarts or writes the user's running profile. The malformed plugin-URL issue, protocol qualification gates, automatic upgrades, and history cleanup are outside this repair. <!-- NEW -->
