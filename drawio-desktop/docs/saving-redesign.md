# Saving and reference storage redesign

New managed gardens use project format 2 and garden protocol 5. Existing protocol 4 registrations keep their storage format. Both formats use the same accepted-state coordinator, permission validator, dependency groups, private views, proposal receipts, and recovery machinery. Collaboration capability flags remain closed. <!-- NEW -->

Immutable reference snapshots live at `.trellis/references/<full SHA-256>.json`. The digest covers canonical JSON and is included in the signed object content. Snapshots are published and verified before acceptance. Operational inventory fields remain in the diagram; reference access reconstructs effective catalogs from the pinned snapshot and those fields. A file is a dependency, never authority to change a reference. No snapshots are garbage-collected. <!-- NEW -->

Main-process and renderer caches have bounded budgets. Opening hydrates definitions asynchronously before synchronous consumers can resolve them. Missing or corrupt definitions make their garden read-only; independent gardens remain editable. Export expands the references in one captured diagram revision, including committed draft edits, without submitting unresolved conflicts. Import and duplication create new-format projects. <!-- NEW -->

Save As in a managed project saves a portable copy and keeps the managed project open. It preserves the project's modified flag, unresolved conflicts, path, and private recovery draft. The destination cannot be the active managed projection. Ordinary standalone Save As retains its existing behavior. Native XML export and managed Save As both preserve Unicode and embed the required definitions. <!-- NEW -->

Ordinary protocol 5 save requests contain changed objects, expected predecessor hashes, a canonical baseline hash, proposal identity, and new reference dependencies. Structural changes retain the existing full-document path. The main process reconstructs the proposal and independently checks dependencies, permissions, structure, and domain effects. Private recovery checkpoints remain independent of the content queue. <!-- NEW -->

Accepted baselines advance even when a rejected edit or newer typing arrives during a save. Native patches reconcile only captured changes. Receipt retries do not republish accepted work and finish interrupted private checkpoints without regressing newer objects. Page navigation, rejected edits, attribution, and presentation updates do not advance content revisions. <!-- NEW -->

The bed-then-Dill reproduction identified succession visibility restoration as a document writer. Opacity and selection order now affect rendered states and nodes rather than model styles or sibling order. Pending-creation permission snapshots are reused until the model, page, or pending changes change. Immutable structural effects can be reused; actor checks and invitation expiry still apply. Opt-in rejection diagnostics retain bounded structural summaries and originating stacks without catalog values or credentials. <!-- NEW -->
