# Saving and reference storage redesign

Managed gardens support only project format 2 and garden protocol 5, using the accepted-state coordinator, permission validator, dependency groups, private views, proposal receipts, and recovery machinery. Protocol 4 support is removed under the assumption that no protocol-4 gardens exist; no migration or compatibility runtime is provided. Collaboration capability flags remain closed. <!-- CHANGE -->

Immutable reference snapshots live at `.trellis/references/<full SHA-256>.json`. The digest covers canonical JSON and is included in the signed object content. Snapshots are published and verified before acceptance. Operational inventory fields remain in the diagram; reference access reconstructs effective catalogs from the pinned snapshot and those fields. A file is a dependency, never authority to change a reference. No snapshots are garbage-collected. <!-- NEW -->

Main-process and renderer caches have bounded budgets. Opening hydrates definitions asynchronously before synchronous consumers can resolve them. Missing or corrupt definitions make their garden read-only; independent gardens remain editable. Export expands the references in one captured diagram revision, including committed draft edits, without submitting unresolved conflicts. Import and duplication create new-format projects. <!-- NEW -->

Save As in a managed project saves a portable copy and keeps the managed project open. It preserves the project's modified flag, unresolved conflicts, path, and private recovery draft. The destination cannot be the active managed projection. Ordinary standalone Save As retains its existing behavior. Native XML export and managed Save As both preserve Unicode and embed the required definitions. <!-- NEW -->

Ordinary protocol 5 save requests contain changed objects, expected predecessor hashes, a canonical baseline hash, proposal identity, and new reference dependencies. Structural changes retain the existing full-document path. The main process reconstructs the proposal and independently checks dependencies, permissions, structure, and domain effects. Private recovery checkpoints remain independent of the content queue. <!-- NEW -->

Accepted baselines advance even when a rejected edit or newer typing arrives during a save. Native patches reconcile only captured changes. Receipt retries do not republish accepted work and finish interrupted private checkpoints without regressing newer objects. Page navigation, rejected edits, attribution, and presentation updates do not advance content revisions. <!-- NEW -->

The bed-then-Dill reproduction identified succession visibility restoration as a document writer. Opacity and selection order now affect rendered states and nodes rather than model styles or sibling order. Pending-creation permission snapshots are reused until the model, page, or pending changes change. Immutable structural effects can be reused; actor checks and invitation expiry still apply. Opt-in rejection diagnostics retain bounded structural summaries and originating stacks without catalog values or credentials. <!-- NEW -->

Smoke measurements do not qualify a release. <!-- CHANGE -->

The archive audit blocks covered reads and enumeration in the protocol-5 directory. <!-- CHANGE -->

The full-editor fixture uses the production protocol-5 new-project path. The staged protocol-4 application and its benchmark workloads have been removed. <!-- CHANGE -->

Separate files can be missing or arrive late; a missing dependency must never silently select factory defaults. Immutable caches can evict definitions and require rehydration. Incremental facts must be invalidated on authoritative replacement. Worker results must match the active document, actor, and accepted position before adoption. Trellis allows one garden editor per application profile; concurrent edits from other computers or isolated profiles can still conflict even when they use one account. <!-- CHANGE -->

The save matrix tests the fresh and 10,000-edit endpoints for protocol 5 once. All seven operations retain five execution samples each (70 total); full-editor qualification retains five pointer-feedback samples (five total). For each operation and workload independently, sort the five samples descending and average the first three. An individual sample may exceed its limit when the three-slowest average passes; no separate maximum limit is imposed. Every raw sample is retained. <!-- CHANGE -->

Split timing retains one real twenty-second autosave wait per workload and uses only the controller's injected quiet clock for the remaining four preparations; execution uses real time. Versioned records separately report wall waits, advances, and countdowns, with no advances allowed during execution. Use `--resume <summary.json>` to reuse completed endpoint workloads only after independently verifying their raw samples, the five-sample/statistic policy, unchanged runtime sources, explicit matching summary/run timing modes, and version-1 `autosaveTiming` records. Unversioned `autosaveScheduling` arrays and inferred timing modes are rejected. Older ten- or thirty-sample reports remain historical evidence and are never truncated to qualify. Extra completed workloads remain extra evidence. <!-- CHANGE -->

The separate pilot is removed; `--pilot` is rejected with a retirement message. Run resumable qualification directly. Historical pilot reports cannot qualify or resume. `--autosave-timing=real` retains all-real diagnostics. The native fixture explicitly requests the automatic-save path after quiet preparation rather than waiting for the editor's native timer to initiate it. Split timing reduces repeated real heartbeat/recovery exposure; focused regressions remain required. Five samples and one repetition reduce the opportunity to detect intermittent failures and launch variation, and the three-slowest average can smooth an individual spike. <!-- CHANGE -->
