# Module creation, accepted policy and placement <!-- CHANGE -->

Managed gardens authorize creation immediately from the existing parent's prior
authority. The native permission guard still validates every transaction,
including private projects and administrators. Proposed grants and ownership
cannot authorize their own introduction. <!-- CHANGE -->

The main process assigns accepted policy an internal, process-wide increasing
`policyRevision`, independent of activity's `observationRevision`. Initialization,
get and successful save replies include the complete accepted policy. The renderer
adopts these snapshots separately: rejecting old activity cannot reject a newer
policy in the same reply. Both replies remain bound to the current document
generation and actor. Older policy cannot replace newer authority. Neither field
changes signed sharing records or protocol versions. <!-- CHANGE -->

`permissionChanges()` remains the sole pending-creation evidence source. Native
edits retain their evidence through claims, queued saves and failures. An accepted
save installs its policy before removing evidence up to the capture's revision;
edits made during that save remain pending. Undone and rejected edits are excluded,
and Redo restores their normal native tracking. Legitimate module commands may
extend the in-flight acquisition batch; its claim drain covers every added root
before persistence. Creating another module does not force an earlier save.
<!-- CHANGE -->

The module factory owns a creation transaction through starter initialization,
final sizing and placement. Roadmap collision orchestration skips existing peer
displacement during creation. A conservative envelope of all new roots preserves
the cluster's relative arrangement and links. Placement tests the requested point,
then grid-aligned nearby candidates ordered by squared distance, y and x, with at
most 256 collision trials. If these fail, the nearest valid location beyond the
occupied bounds is used. Only new roots are translated; selection and reveal
follow accepted completion. Manual move and resize keep their existing behavior.
<!-- CHANGE -->

Initialization exceptions reverse the command's changes. Permission rejection
uses the existing native edit rollback and meaningful rejection message; the
factory never selects a discarded result. The Users undo insertion guard excludes
already rejected edits before native history insertion, preserving valid Redo
history as well as avoiding invalid Undo entries. No saved-diagram migration or
automatic reapplication of retained drafts is involved. <!-- CHANGE -->

The envelope can be conservative for sparse clusters, and dense layouts can
require placement beyond occupied bounds. Selection and viewport reveal expose
the result. Independent recovery and heartbeats continue while the twenty-second
save pause is pending; continuous editing may defer project persistence until
manual Save. <!-- CHANGE -->
