# Garden Projects library

The splash retains Create, Open, Support, Change license, and contact controls. Completed licensing removes the close control and prevents Escape or backdrop dismissal; incomplete licensing retains its existing exit flow. It displays the identity session's username, independent of the name recorded on the license. Create/Open launch the same Garden Projects dialog with creation/list focus. <!-- CHANGE -->

Returning Home automatically saves a modified document and closes all its pages in the current window before showing the splash. Untitled documents use the native save-location dialog; untouched blanks close without saving. Canceling or failing a save leaves the editor and recovery draft available. Busy saves, renames, and project retirement must finish before retrying Home. Other windows stay open; opening Garden Projects alone continues to preserve the editor. <!-- NEW -->

## Projects and identity controls

`TrellisGardenHome.showProjects(ui, { focus: 'create' | 'open' })` owns authentication, identity settings, Your city, maximum distance, search, and the project lists. The title, top-right account menu, and Projects/Trash tabs remain above the scrolling body. Garden communities, ungrouped Shared garden projects, and Private garden projects have separate sections. Availability refreshes preserve filter and form drafts. Ordinary Open routes here; Browse files opens the explicit native file picker. <!-- CHANGE -->

Every disclosure marker is on the right. A folded section hides creation controls and content while retaining its title and counters. Communities contain Joined gardens (initially expanded) and Not joined gardens (initially collapsed). Fold preferences are local to each identity; older shared-section preferences seed both new shared sections. Search temporarily reveals matches without overwriting saved folds. Account, city, and project-action popovers close on outside clicks, focus leaving, selection, or Escape; an outside click still activates its intended target. <!-- NEW -->

Both project-creation buttons create an identity-library entry. Starter initialization uses `graph.__trellisModules.createModuleAtPoint` after Users, Tasks, and Roadmap are ready, then saves the project. Shared creation invokes `trellisShareGardenProject`, the existing Dashboard invitation flow. Failed setup offers a retry for the same project rather than creating another entry. Newly created entries carry `starterPending`; opening an interrupted creation finishes its starter. After a successful save, `completeStarter({ path })` verifies the watched registered document and durably clears that flag, so later intentional empty saves are never seeded again. Closing a creation/browser cancels late navigation, and initialization checks its document before applying changes. <!-- CHANGE -->

Private contains standalone local files and identity projects with fewer than two enabled, accepted users with canvas access. Shared requires managed sharing and at least two such users. Pending invitations are excluded. Revoked linked-user access removes the project from the accessible list. These categories never move disk folders.

## Metadata and bridges

The existing `trellisGardenLibrary` bridge retains its API names and `gardens` response for compatibility. It adds:

- `listLocal()` — direct `.drawio` children of the device's configured folder, isolating bad files and excluding conflict copies.
- `completeStarter({ path })` — finish saved starter initialization under the same watched-document authority as import.
- `selectLocalFolder()` — a native folder selection; the main process stores the resulting path.
- `cities()` — valid coordinates from the existing live city catalog, falling back to the bundled database before first initialization.
- `getReferenceCity()` / `setReferenceCity({ cityId })` — signed identity metadata; `null` clears the reference.

The default standalone folder is Documents/Trellis/Local Garden Projects. Files selected with Browse remain where they are and are not automatically imported.

Library results include classification, nullable user/seed counts, nearest distance, module-city summaries, cache timestamps, and per-project metadata errors. Optional `people` summaries contain `userCount`, `onlineCount`, opaque `memberKeys`/`onlineMemberKeys`, and `membershipComplete`/`presenceComplete`. Keys are scoped to the viewing identity and this process, shared consistently with community listings, and never synchronized. Portable membership mappings stay in main-process metadata rather than renderer summaries. Deduplication uses both registered paths and diagram identities, so a standalone copy does not duplicate its library project. Summary changes are signed into the existing catalog; reference-city records live in a separate directory under synchronized identity metadata. Authentication events and on-disk project paths retain their existing formats. Browse can isolate an unverifiable catalog record; mutation reads still require strict verification. <!-- CHANGE -->

Your city opens a searchable Country → Province/State/Territory → City picker using the existing catalog. Closed geographic groups populate lazily. The saved city continues to synchronize with the identity. Max distance uses kilometers, starts unlimited, and is remembered per identity on this device. Blank clears the limit; finite values greater than or equal to zero are valid. Invalid input leaves the last valid filter in force, and filtering is disabled until a city is selected. <!-- CHANGE -->

Shared projects and community gardens match when their nearest resolved garden-module city is at or inside the radius. They sort nearest first and then by name, with unknown distances last; without a city they sort alphabetically. Private projects and Trash ignore the radius. Unknown-distance shared gardens are hidden while a radius is active, with an explanatory count. Text and distance filters combine, hiding empty filtered communities and membership groups. Counters show matching/overall entity totals and people belonging to matching gardens. Missing metadata never becomes an invented zero. <!-- NEW -->

People counts deduplicate portable identities and their approved devices, include the current user, and exclude invitations and inactive access. Online means at least one eligible device is connected as observed by this device. Connection snapshots expire after 15 seconds and become unavailable after polling failure or shutdown. Partial observations show a confirmed minimum or “online unknown”; incomplete cross-project membership also remains labeled. Presence is never published in signed metadata and does not establish whether a person is logged in or editing elsewhere. <!-- NEW -->

Seeds count authorized devices reporting a complete project folder. Remote candidates must be connected and report valid folder sharing, 100% completion, no needed items, and a nonempty global folder. An eligible complete local device also counts. Paused/nonsharing peers do not count; failed or incomplete telemetry reports Unknown. Counts indicate reported data availability, not editor presence or guaranteed delivery.

## Project names and personal filenames <!-- NEW -->

Library projects keep their existing stable `diagramId` when renamed. The shared name lives in document identity metadata as `trellis_project_name`; only an active project administrator may change it. Main-process commands and signed collaboration replay enforce the same restriction, including changes made through ordinary metadata edits. Garden-module names and standalone files remain independent. <!-- NEW -->

Each identity can set an optional personal suffix, synchronized through signed `project-suffixes` metadata keyed by `diagramId`. Project rows and editor titles display `Shared name - My suffix`; an empty suffix removes the separator. Suffixes do not change roles or permissions and never enter shared XML, invitation labels, or public project descriptors. `rename({ diagramId, name })` changes the shared name; `setSuffix({ diagramId, suffix })` changes only the authenticated identity's suffix. Results expose `projectName`, `suffix`, `displayName`, actual `filename`, capabilities, and pending filename errors; the existing `name` field is the composed display name. <!-- NEW -->

Local `.drawio` filenames follow the composed name. The naming dialog previews conversion of unsupported filesystem characters. Display text is retained; portable filenames replace invalid/control characters, trim trailing dots/spaces, protect Windows reserved names, and truncate at Unicode boundaries. Shared names allow 120 characters and personal suffixes allow 80. <!-- NEW -->

All managed library projects use v2 local projections. Version 1 sharing is unsupported. Available old diagrams remain visible as **Local only · Sharing off**, with native local editing and assets; missing copies are hidden, and shared-management controls are omitted. Their catalog records and registration data remain intact, while naming, downloads, communities, and lifecycle maintenance process current projects only. There is no upgrade, conversion, or re-sharing workflow. Application-wide v2 projections remain neutral while the identity's own copy downloads through existing device approval. Ordinary renames preserve document and sharing identities; coordinator recovery creates a replacement sharing identity and new invitations. <!-- CHANGE -->

Renames are serialized with projection saves, journaled outside synchronized project data, and never overwrite a destination file. Every open editor follows the new path without reopening or replacing its unsaved model. Draft paths and recent files follow the move. Filename collisions, busy editors, and filesystem errors preserve the original and report a pending update for retry. Externally renamed files are recognized by document identity; their filenames never become shared names or personal suffixes. Administrators can rename downloaded v2 projects offline using existing collaboration conflict handling. <!-- NEW -->

## Verification

### On-demand dialog snapshots <!-- CHANGE -->

Garden communities, Shared projects, Private projects, Access requests, and Trash load independently on the first dialog opening for each portable identity in each app window. Signed-out browsing has its own entry. Public display data, section status, and successful timestamps remain in memory until that window closes, including across logout and identity switches. Credentials and form drafts are never part of this cache. Logout immediately hides the prior identity's rows and invalidates open prompts. <!-- CHANGE -->

Reopening, switching Projects/Trash, transport status events, and elapsed time perform no metadata refresh. Each section has a Reload control, disabled only while that section is loading, and a static locale-formatted Updated-at time with the full date and time exposed to assistive technology. Reload failures retain previous rows and timestamps and show a section-local error; retry is always explicit. Header loading remains visible when folded. Unchanged project rows retain their nodes, focus, expanded details, search, drafts, and scroll. <!-- CHANGE -->

Pending initial reads can finish into the window cache while the dialog is closed and are reused on reopening. They never write detached UI, and obsolete login-generation responses are discarded. Section reloads can share backend reads but publish only their selected category and necessary garden transfers. Private standalone scanning waits for recoverable local Trash moves; managed project rows and communities load independently of that recovery. <!-- CHANGE -->

Community Reload reads both accessible and unjoined discovery data from current verified state. The main process retains verified-file caches, not a login-frozen display snapshot. Other incoming changes, availability, counts, and access changes remain stale until the relevant Reload. User-initiated edits update their affected rows immediately from results or targeted reads. Actions always validate current authorization. Background synchronization, naming recovery, and approximately five-second presence observations continue independently of the dialog, with no change to synchronization policy. <!-- CHANGE -->

Unjoined gardens show total users without active-user counts. Community active-user aggregates explicitly cover accessible gardens. Connection observations are sampled independently of garden journal processing; unavailable or expired telemetry retains the existing unknown-presence semantics. <!-- NEW -->

`trellisGardenCommunities.list({scope: 'accessible' | 'discovery'})` adds scoped browsing while the no-argument call retains its existing behavior. `trellisGardenLibrary.list({diagramId})` supports targeted reads after edits. Public session data adds a process-local `generation` number to distinguish repeated logins by the same identity; it contains no credentials and is not persisted. Browsing is read-only: naming reconciliation, filename recovery, replacement-share adoption, and durable metadata publication stay in mutation/background paths. No persistent schema migration is required. <!-- NEW -->

Optional renderer timing observations use `window.TrellisGardenHomeTiming({phase, milliseconds})`; normal operation produces no timing logs. ## Delete, Leave, and Trash <!-- NEW -->

All library-owned buttons, including identity and community forms, reuse the shared Trellis semantic contract: blue for opening/navigation, green for creation/save/restore/approval, red outline for cancellation/closure, solid red for destructive actions, and neutral for utilities/editing. Projects and Trash show the shared active blue state. <!-- CHANGE -->

**Move to Trash…**, **Leave project…**, and **Delete permanently…** open modal confirmations above the mounted library. Each names the project and explains its consequences; permanent deletion requires an explicit button without typed-name confirmation. Cancel receives initial focus; Tab stays in the prompt, Escape/Cancel/close dismiss it, and backdrop clicks are ignored. Submission blocks dismissal and duplicate requests, with failures remaining visible for retry. Cancellation restores the actions trigger (or search if its row disappeared) while retaining search, scroll, and expanded sections. Existing successor selection and unsaved Save/Discard/Cancel choices remain; suffix editing and restore filename forms stay inline. Identity changes, editor changes before submission, and library closure invalidate stale callbacks. <!-- CHANGE -->

Project rows use **Downloaded**, **Not downloaded**, or **Local file**, with aligned Open and accessible actions controls. Device-download removal and offline pinning are omitted from this dialog. The Private/Shared headings describe membership, not deletion authority. <!-- NEW -->

**Move to Trash** is available to the sole active, identity-linked administrator. It removes the active row and moves managed files to Trellis Trash on each paired device as it reconnects. A signed, sole-user catalog snapshot permits moving an unavailable entry to Trash without downloading it. Each device revalidates the actual roster before moving or purging bytes; changed membership preserves files and reports a conflict in Trash. Pending invitations are revoked when the holding device applies deletion. Restore never reactivates invitations. <!-- CHANGE -->

**Leave project** requires another connected, accessible member with a compatible client. The last administrator chooses a connected successor. A departing coordinator also hands coordination to that successor or a connected existing administrator. All remaining approved devices must have advertised handover support at least once. Unavailable telemetry never counts as a connection. The row remains marked Leaving until signed readiness, applied-membership, receipt-delivery, and finalization records complete. Other members retain the project and historical attribution. Rejoining requires a fresh invitation and approval. <!-- NEW -->

Lifecycle records live in the identity metadata directory `project-lifecycle`, separately from catalog and authentication events. Records name causal predecessors; concurrent deletion wins over restoration, and purge markers remain terminal. Startup fences retired folders before starting synchronization. Background refresh applies lifecycle records before processing old download requests. Renderer bridges add `actions`, `trash`, `restore`, `purge`, `leave`, and `listTrash`; existing active-list and catalog formats remain compatible. Older clients must be updated to honor these records. <!-- NEW -->

Managed folders move outside synchronization into the transport profile’s `project-trash`. Local move journals retain fingerprints and resume interrupted operations. Cross-volume copies must verify before removing their sources. Restore and purge failures remain visible and retryable in Trash. Trash retains data indefinitely until explicit permanent deletion; exported and disconnected copies cannot be guaranteed erased. <!-- NEW -->

Standalone files use device-local Trash under the application profile, including while signed out. Only the selected ordinary `.drawio` file moves; neighboring files and assets stay in place. Restoration uses the original directory and an editable filename, rejecting collisions without overwriting either file. <!-- NEW -->

Open editors prepare retirement through sender-correlated IPC. Unsaved remote drafts are flushed to `project-draft-recovery` in the application profile before the editor closes. An unanswered preparation or an intervening edit blocks filesystem removal. Local confirmations offer Save, Discard, or Cancel when needed. <!-- NEW -->

Coordinator transitions are membership records signed by the previously pinned coordinator. Offline peers replay the chain in version order, while the original v2 genesis key remains pinned independently. The departing peer remains a transport recipient only through receipt delivery; its editing authority is already retired. There is no automatic coordinator takeover. <!-- NEW -->
